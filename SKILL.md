Ты собираешь ежедневный «Химический новостной радар» для департамента международного развития АО «Росхим». Работаешь в облачной cloud-сессии Claude Code Routine — репозиторий склонирован в текущую рабочую директорию, локальных путей `~/.claude/...` и `~/Desktop/...` здесь нет и быть не должно.

ТВОЯ ЗОНА ОТВЕТСТВЕННОСТИ — СОДЕРЖАНИЕ И ДАТЫ. Оформление выпуска (нумерация и названия рубрик, набор карточек регионов, чип возраста, подписи важности, дата выпуска, дозапись журнала, отправка письма) целиком задаёт `build.py` — не пиши эти поля в issue.json, они будут проигнорированы.

ГЛАВНОЕ ТРЕБОВАНИЕ — СВЕЖЕСТЬ. Это ежедневник: он должен показывать новое за сутки, а не повторять фон. Поисковая выдача регулярно подсовывает материалы месячной и годовой давности — их брать НЕЛЬЗЯ. У каждой новости, каждого буллета региона со ссылкой и каждой плитки тикера ОБЯЗАТЕЛЬНО проставь `pub_date` (ISO), проверив реальную дату публикации у самого источника (если в выдаче даты нет — открой статью через WebFetch и посмотри). Не угадывай даты и никогда не ставь дату «на глаз» или из будущего — build.py это проверяет и выбрасывает. Если новость — это само событие, а статья вышла раньше (пошлина вступила в силу, стартовал ремонт, закрылся тендер), добавь `event_date`.

Что build.py выбрасывает жёстко: новости старше 3 дней; буллеты регионов старше 30 дней; плитки тикера старше 2 дней; пункты без ссылки на источник; ссылки на SEO-витрины отчётов из блок-листа; повторы URL или заголовка из выпусков за последние 14 дней (провести долгий сюжет можно только с "update": true и только при новой вехе). Пустая рубрика ЛУЧШЕ, чем несвежий пункт. Полностью пустой выпуск не соберётся вовсе.

ШАГ 1. Прочитай конфиг `./config.md` (в корне репозитория) — цель, разделение ответственности, пайплайн, регионы, продуктовый watchlist (периметр «Росхим»), рубрики, правила свежести/антиповтора, спека тикера и трендов, схема issue.json, пул запросов, логика отбора. Следуй ему строго.

ШАГ 2. Прочитай журнал `./history.jsonl` (что уже освещалось за ~14 дней), чтобы не повторяться. Этот файл коммитится в репозиторий предыдущим запуском — если он отсутствует или пуст, значит это первый запуск.

ШАГ 3. Собери СВЕЖИЕ новости инструментом WebSearch по пулу запросов из конфига (подставь текущие месяц/год и добавляй конкретные свежие даты в запрос). Покрой 6 новостных рубрик (urgent, geo, capacity, reg, energy, ru) и карточки регионов (Китай/ЛатАм/Африка/MENA детально; Европа/Сев. Америка обзорно). Приоритет — продуктовый периметр «Росхим» (содовый, хлорно-щелочной, индустриальный, агробиохимический кластеры, нефтегазохимия) и санкции/барьеры по химэкспорту РФ, плюс широкий охват. Новости внутреннего рынка РФ — только в рубрику ru (и, при высокой значимости, в urgent); в рубриках geo/capacity/reg/energy их быть не должно — build.py переносит их сам и пишет об этом предупреждение. ПРОВЕРЬ ДАТУ каждого источника перед включением.

ШАГ 4. Тренды (8-я секция): если сегодня ПОНЕДЕЛЬНИК или файла `./trends.json` нет / он старше 7 дней — пересобери 3–5 ключевых трендов месяца и перезапиши trends.json, обновив "updated_iso" (ISO-дата). Иначе не трогай файл. build.py сам подставит тренды в выпуск.

ШАГ 5. Собери и запиши `./issue.json` строго по схеме из конфига: date_iso, regions_line, ticker (ОПЕРАЦИОННЫЕ сигналы — Brent/Ормуз/Красное море/форс-мажоры, у каждой плитки pub_date), sections с id urgent/geo/capacity/reg/energy/ru, regions_cards с именами Китай/ЛатАм/Африка/MENA/Европа/«Сев. Америка». У каждого пункта — source_url и pub_date.

ШАГ 6. Установи зависимости при необходимости (`python3 -m pip install --user reportlab`), затем запусти `python3 build.py`. ОБЯЗАТЕЛЬНО прочитай его вывод: он печатает отброшенное с причинами, счётчик пунктов по рубрикам, предупреждения и результат отправки письма («Письмо отправлено: ...» или предупреждение о недостающих переменных окружения GMAIL_ADDRESS/GMAIL_APP_PASSWORD/DIGEST_RECIPIENTS — если видишь это предупреждение, остановись и сообщи об этом в резюме запуска, дальше можно не разбираться, это настройка environment variables routine, не твоя зона). Если рубрики опустели или всего пунктов мало — вернись к ШАГУ 3 и доищи действительно свежие события (не ослабляй правила и не подделывай даты), затем пересобери. Проверить, ничего не записывая, можно ключом `--dry-run`.

ШАГ 7. Если build.py отработал успешно (файлы в `./out/` обновились и письмо ушло) — закоммить и запушь в main обновлённые состояние-файлы, чтобы следующий запуск видел актуальный журнал:
```
git add history.jsonl trends.json issue.json
git commit -m "Дайджест за $(date +%d.%m.%Y)"
git push origin main
```
Если пуш отклонён (нет прав на прямой пуш в main) — значит в настройках routine не включён "Allow unrestricted branch pushes" для этого репозитория; сообщи об этом явно в резюме запуска, это тоже не твоя зона, а настройка на стороне пользователя.

Зависимость: reportlab. Успех = в `./out/` появились свежие ДайджестРХ-<сегодня в формате ДД-ММ-ГГГГ>.pdf/.html, каждая новость реально не старше 3 дней и подтверждена ссылкой, письмо с PDF ушло получателям, history.jsonl закоммичен и запушен.
